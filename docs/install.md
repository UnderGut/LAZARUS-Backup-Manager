# Установка и первый запуск

Как поставить `lazarus` одной командой и пройти первичную настройку: выбрать цель (панель / бот), включить уведомления, шифрование, авто-бэкап и копию в облако.

Установка — на том сервере, где стоит **Remnawave Panel** (или бот `rwp_shop`). Docker и `docker compose` v2 должны быть уже установлены и запущены. Скрипт ничего не удаляет и не перезапускает — он только читает контейнеры и делает дампы.

---

## TL;DR — 3 шага для новичка

1. Поставьте `lazarus` одной командой (от root):
   ```bash
   curl -sSL https://raw.githubusercontent.com/UnderGut/LAZARUS-Backup-Manager/main/lazarus-backup -o /usr/local/bin/lazarus && chmod +x /usr/local/bin/lazarus
   ```
2. Запустите:
   ```bash
   lazarus
   ```
   При **первом запуске** скрипт сам доустановится в `/opt/lazarus-backup/`, спросит **что бэкапим** (панель / бот / обе) и запустит мастер защиты.
3. В мастере пройдите **4 шага** (уведомления · шифрование · авто-бэкап · облако). Любой шаг можно пропустить нажатием Enter — вернуться к нему всегда можно позже.

---

## Требования

| Компонент | Зачем | Проверка |
|---|---|---|
| **root** | установка в `/usr/local/bin` и `/opt`, доступ к Docker | `whoami` → `root` |
| **Docker + `docker compose` v2** | дампы БД и чтение контейнеров | `docker compose version` |
| **`tar`, `gzip`, `openssl`** | архивация и шифрование (AES-256) | обычно есть в базовой системе |
| **`curl` или `wget`** | загрузка и авто-обновление скрипта | `curl --version` |
| `find`, `du`, `date` | служебные операции | есть в coreutils |

При старте `lazarus` сам проверяет зависимости. Если чего-то из обязательного нет — покажет, что доставить (`apt install …`), и остановится.

**Опциональные пакеты** (без них работает, но часть фич выключена) — скрипт про них предупредит, но не остановится:

| Пакет | Что даёт |
|---|---|
| `zstd` | сжатие `COMPRESSION="zstd"` (быстрее ~2.5×, архив ~11% меньше). Без него — всегда `gzip`. |
| `rsync` | restore файлов в режиме синхронизации папок |
| `flock` | защита от параллельного запуска (два бэкапа разом) |
| `sha256sum` | проверка целостности при авто-обновлении |
| `realpath` | миграция старых установок |
| `sshpass` | вход по root-паролю при переносе панели (мастер предложит поставить) |

Ставятся обычным пакетным менеджером, например:
```bash
apt install zstd rsync
```

## Как работает установка

Команда из TL;DR кладёт файл в `/usr/local/bin/lazarus` и делает его исполняемым. Дальше при **первом** запуске скрипт сам себя устанавливает «по-настоящему»:

1. Создаёт каталог `/opt/lazarus-backup/`.
2. Копирует туда себя как `/opt/lazarus-backup/lazarus-backup`.
3. Пересоздаёт symlink `/usr/local/bin/lazarus` → `/opt/lazarus-backup/lazarus-backup`.
4. Ставит `logrotate`-правило для своих логов (если в системе есть `/etc/logrotate.d`).
5. Перезапускает сам себя из установленного пути — и вы попадаете в первичную настройку.

То есть команду `lazarus` вы набираете всегда, а живёт скрипт в `/opt/lazarus-backup/`. Каталог бэкапов — `/opt/lazarus-backup/backup/` (права `0700`).

> **Если сеть недоступна во время авто-установки** — скрипт использует уже скачанный файл (тот, что вы положили в `/usr/local/bin`). Отдельно качать ничего не нужно.

### Обновление

Скрипт обновляется сам:
```bash
lazarus update
```
Источник обновлений — единственное подписанное зеркало `raw.githubusercontent.com`; при наличии `.sha256`-манифеста целостность проверяется перед заменой.

## Первый запуск

Запустите просто:
```bash
lazarus
```

### Шаг 1 — что бэкапим?

Скрипт сам осмотрит сервер: ищет каталог панели, контейнер БД `remnawave-db`, каталог бота (`rwp_shop` / `rwp-shop`). Найденное подсвечивается, а рекомендуемый пункт помечен `(рекомендуется)`:

```
Первичная настройка — что бэкапим?

 1. Remnawave Panel (рекомендуется) (найдено: /opt/remnawave)
    бэкап /opt/remnawave + дамп БД + роли (globals) + infra-billing (если найден)
 2. Telegram-бот rwp_shop (вторичная цель)
 3. Панель + Бот (обе цели, один прогон)

Выбор (Enter = 1, Панель):
```

- **Панель — основная цель.** Бэкапит каталог панели, дамп БД, роли кластера (globals) и infra-billing, если он обнаружен.
- Если на сервере найдены **и панель, и бот** — по умолчанию предлагается пункт **3 (обе)**.
- Имя контейнера БД панели подставляется автоматически (даже если оно нестандартное) — вводить вручную ничего не нужно.

Если обнаружен **infra-billing** или **БД ИИ-саппорта (KB)** бота — скрипт отдельно спросит, бэкапить ли их вместе (`Y` = да). Передумать можно потом: пункт **99 (Расширенный режим) → Настройки → Доп. компоненты**.

### Шаг 2 — мастер защиты (4 шага)

Сразу после выбора цели открывается мастер. Enter на любом шаге = пропустить.

```
Настройка бэкапа
  4 шага: уведомления · шифрование · авто-бэкап · копия в облако
  Любой шаг можно пропустить — просто нажмите Enter.
```

**[1/4] Уведомления в Telegram.** Бот пришлёт результат каждого бэкапа. Токен — у `@BotFather`, ваш Chat ID — у `@userinfobot`.
```
  Токен бота (Enter — пропустить): 1234567890:AA...демо...
  Ваш Chat ID: 100000000
```

**[2/4] Шифрование архивов (AES-256).** Без пароля копия базы данных (данные пользователей, ключи доступа) лежит в открытом виде.
```
  Пароль шифрования (Enter — пропустить): ********
  Повторите пароль: ********
```
Пароль хранится отдельным файлом `/opt/lazarus-backup/.password` с правами `0600` (не в открытом виде в конфиге). Не теряйте его — без пароля старые `.enc`-архивы не восстановить.

**[3/4] Авто-бэкап по расписанию.** Пишет задачу в `crontab`:
```
  1. Ежедневно в 04:00 (рекомендуется)
  2. Каждые 6 часов
  3. Свой интервал в минутах
```

**[4/4] Копия вне сервера (облако).** Если сервер выйдет из строя, локальные бэкапы пропадут вместе с ним. Здесь можно подключить внешнее хранилище (S3 / FTP / WebDAV / Rclone):
```
  Настроить копию в облако сейчас? (y/д — да, Enter — пропустить):
```

В конце — сводка готовности и возврат в меню.

## Проверка: «что нашлось»

Отдельная команда показывает, какие стеки скрипт видит на сервере (только чтение, конфиг не меняется):

```bash
lazarus stacks
```

Пример вывода:
```
Обнаруженные стеки:
  Панель:        /opt/remnawave  app=remnawave  db=remnawave-db
  infra-billing: app=—  db=—
  Бот:           /opt/rwp-shop  app=rwp_shop  db=rwp_shop_db

Конфиг (активная цель panel): path=/opt/remnawave db=remnawave-db
```

Если конфиг расходится с реальностью (например, имя контейнера БД не совпадает с обнаруженным) — команда подсветит расхождение жёлтым `⚠`, но **не** будет ничего менять сама. Это удобная проверка после установки: убедиться, что цель определена верно.

## Где что лежит

| Путь | Что это |
|---|---|
| `/usr/local/bin/lazarus` | команда (symlink на установленный скрипт) |
| `/opt/lazarus-backup/lazarus-backup` | сам скрипт |
| `/opt/lazarus-backup/config.env` | конфигурация (права `0600`) |
| `/opt/lazarus-backup/.password` | пароль шифрования (права `0600`) |
| `/opt/lazarus-backup/backup/` | локальные архивы (права `0700`) |
| `/var/log/lazarus_backup.log` | лог cron-бэкапов |

Конфиг создаётся при первом запуске и обновляется через меню/мастер. Править его руками обычно не нужно — все настройки есть в интерфейсе. Полный список ключей и значений по умолчанию — в [CONFIG_REFERENCE](../CONFIG_REFERENCE.md).

## Частые проблемы

| Симптом | Причина / решение |
|---|---|
| `Запустите скрипт с правами root (sudo)!` | Установка и доступ к Docker требуют root. Запускайте от root или через `sudo`. |
| `'docker compose' plugin is required but not found` | Нет плагина Compose v2. Поставьте `docker-compose-plugin`. Проверка: `docker compose version`. |
| `Missing dependencies: …` | Нет обязательного пакета (`tar`/`gzip`/`openssl`/`curl`…). Доставьте подсказанной командой `apt install …`. |
| `Для установки нужен curl или wget!` | Нет ни `curl`, ни `wget`. Поставьте любой из них. |
| `COMPRESSION=zstd, но zstd не установлен!` | В конфиге выбран zstd, а пакета нет. `apt install zstd` **или** смените `COMPRESSION` на `gzip` в `config.env`. |
| Панель/бот не нашлись автоматически | Проверьте `lazarus stacks`. Нестандартные пути/имена можно задать в `config.env` (см. [CONFIG_REFERENCE](../CONFIG_REFERENCE.md)). |
