# Шифрование бэкапов

Как включить AES-256 шифрование архивов, что даёт формат v2 (HMAC), и как обновить старые архивы.

Архив панели содержит **дамп базы** (данные пользователей, ключи доступа, токены). Если бэкап уходит в облако/S3/Telegram — без шифрования его прочитает любой, кто добудет файл. Шифрование делает архив бесполезным без пароля.

---

## TL;DR — 3 шага для новичка

1. Запустите мастер защиты или откройте `lazarus` → **Настройки → Шифрование**.
2. Задайте пароль (вводится дважды, скрыто). Он сохранится в отдельный файл `.password` с правами `600`.
3. Готово — следующие бэкапы шифруются автоматически (`🔒 Encrypted` в отчёте). **Запишите пароль отдельно: без него восстановление невозможно.**

> Один раз задали пароль — больше ничего делать не нужно. Каждый бэкап шифруется сам; если пароль задан, но шифрование сорвалось, lazarus **НЕ отправит** архив открытым текстом молча.

---

## Как включить

### Вариант A — мастер защиты (первый запуск / кнопка «Q»)

Мастер `Настройка бэкапа` вызывается автоматически при первом запуске и по клавише **Q** с главного дашборда. Шаг **[2/4] Шифрование архивов (AES-256)**:

```
[2/4] Шифрование архивов (AES-256)
  Без пароля копия базы данных (данные пользователей, ключи доступа)
  лежит в открытом виде — её прочитает любой, кто добудет файл бэкапа.
  Пароль шифрования (Enter — пропустить): ********
  Повторите пароль: ********
Шифрование включено
```

Если шифрование уже настроено — шаг не тупиковый: **Enter** оставляет как есть, **1** меняет пароль.

### Вариант B — Настройки → Шифрование

```
lazarus
```
→ **Настройки** → раздел **4. Шифрование (пароль AES-256)**:

```
Новый пароль (пусто = отключить шифрование): ********
Повторите пароль для подтверждения: ********
✓ Шифрование включено (пароль N символов сохранён)
  Файл: /opt/lazarus-backup/.password
Важно: запомните или сохраните пароль — без него восстановление невозможно.
```

Пустой ввод в этом пункте = **отключить** шифрование (запросит явное подтверждение и удалит файл пароля).

### Где хранится пароль

Пароль лежит **не** в `config.env`, а в отдельном файле `BACKUP_PASSWORD_FILE` (по умолчанию `$INSTALL_DIR/.password`, т.е. `/opt/lazarus-backup/.password`) с правами **`chmod 600`** (читает только владелец).

- Запись пароля проверяется побайтно: при нехватке места / частичной записи файл удаляется, а не остаётся «огрызком».
- Если `chmod 600` не применился (ACL, mount-опции) — файл удаляется, чтобы пароль не оставался читаемым для других.
- Устаревшая переменная `BACKUP_PASSWORD` в `config.env` при старте автоматически **мигрирует** в файл и затирается. Оставляйте её пустой.
- Путь пароля обязан быть **внутри** каталога установки — попытка указать `/etc/passwd` и т.п. отклоняется.

## Что даёт формат v2 (LAZ2 + HMAC)

Свежие зашифрованные архивы (`.enc`) пишутся в конверте **v2**: `LAZ2` (сигнатура) + шифртекст (AES-256-CBC, PBKDF2, 100 000 итераций, соль) + **HMAC-SHA256** в конце.

HMAC даёт две вещи, которых нет у голого AES:

| Возможность | Что это значит |
|---|---|
| **Детект неверного пароля ДО расшифровки** | Проверка подписи мгновенно скажет «пароль не тот», не пытаясь распаковать мусор. |
| **Детект подмены байтов** | Если файл повредили при передаче или **намеренно подменили** шифртекст, проверка HMAC провалится ещё до decrypt (защита от targeted-ciphertext атак). |

При каждом бэкапе после шифрования выполняется **verify** (проверка HMAC + пробная расшифровка + тест целостности сжатия) — и только после успешной проверки удаляется исходный незашифрованный файл. Битый/недешифруемый архив не будет отгружен как «успех».

## Enforcement: пароль задан → plaintext молча не уходит

Если пароль задан, но шифрование сорвалось (нет `openssl`, кончилось место, timeout), lazarus **не отправит незашифрованный дамп БД** незаметно:

- **В cron / non-interactive** — бэкап **отменяется** (`return 1`), в лог и Telegram-алерт уходит `Шифрование задано, но провалилось · Незашифрованный бэкап НЕ отправлен`.
- **В интерактиве** — чтобы всё же отгрузить открытым текстом, нужно ввести слово-подтверждение:

```
Архив содержит данные БД. Отправить НЕЗАШИФРОВАННЫМ?
Введите PLAINTEXT для подтверждения (иначе бэкап будет отменён):
> 
```

Только точное `PLAINTEXT` пропустит незашифрованный архив (статус в отчёте станет `⚠️ UNENCRYPTED`). Любой другой ввод = отмена.

> Таймаут шифрования регулируется `ENCRYPT_TIMEOUT_SEC` (по умолчанию `1800` сек; `0` — отключить). Для очень больших архивов на слабом CPU может понадобиться увеличить.

## Обратная совместимость со старыми `.enc`

Старые архивы формата **v1** (сигнатура `Salted__`, без HMAC) **читаются и восстанавливаются как прежде** — ничего конвертировать для восстановления не обязательно. Разница только в защите: у v1 нет быстрого детекта неверного пароля и нет проверки подмены байтов.

После бэкапа lazarus сам замечает архивы v1 и подсказывает:

```
Найдено N backup'ов в формате v1 (без HMAC). Запустите 'lazarus migrate-v2' для конверсии.
```

---

## Конверсия старых архивов: `lazarus migrate-v2`

Команда пересобирает v1-архивы в v2 (добавляет HMAC), не требуя пересоздания бэкапа:

```bash
lazarus migrate-v2
```

Интерактивно покажет список найденных v1-файлов и спросит подтверждение. Для cron / SSH без TTY — автоматический режим:

```bash
lazarus migrate-v2 --yes
```

Как это работает (безопасно для единственной копии):

1. **decrypt** v1 → проверка, что расшифрованное — валидный архив (иначе пропуск, оригинал не тронут).
2. **re-encrypt** → v2-конверт.
3. **round-trip verify**: v2 расшифровывается обратно и проверяется целостность — ещё **до** перезаписи.
4. **атомарная замена** (`mv` в той же ФС). Оригинал удаляется **только** после успешной верификации.

Для конверсии нужен `BACKUP_PASSWORD` (тот же пароль, которым архивы шифровались) — без него миграция невозможна. В non-interactive без `--yes` конверсия откладывается: создаётся маркер, и подсказка появится при следующем интерактивном запуске.

## Важное: смена пароля НЕ перешифровывает старые архивы

Когда вы меняете пароль шифрования, **уже созданные `.enc`-файлы остаются зашифрованными на ПРЕЖНЕМ пароле**. lazarus предупреждает об этом прямо в меню:

```
N ранее созданных .enc-бэкапов остаются на ПРЕЖНЕМ пароле — храните и его.
```

Практический вывод:

- **Храните все пароли, которыми когда-либо шифровали архивы.** Для восстановления конкретного архива нужен тот пароль, что действовал на момент его создания.
- Смена пароля влияет **только на будущие** бэкапы.
- `migrate-v2` тоже **не меняет пароль** — конвертирует формат под тем же паролем.
- Отключение шифрования (пустой пароль) удаляет файл пароля и делает **новые** бэкапы открытыми; старые `.enc` расшифровкой это не затрагивает.

## Частые вопросы

| Симптом | Причина / решение |
|---|---|
| В «Защите» на дашборде: `✗ пароль НЕЧИТАЕМ` | Файл `.password` есть, но пуст / вне каталога установки / без прав чтения. Задайте пароль заново через Настройки → Шифрование. |
| `Ошибка шифрования архива!` в cron | Нет `openssl`, кончилось место или сработал `ENCRYPT_TIMEOUT_SEC`. Бэкап отменён (plaintext не отправлен) — проверьте место/openssl и повторите. |
| При восстановлении «пароль не тот» | Для v2 это детект неверного пароля до decrypt. Для старого `.enc` нужен пароль, действовавший на момент создания архива. |
| `migrate-v2`: «BACKUP_PASSWORD не задан» | Миграции нужен текущий пароль архивов. Убедитесь, что шифрование включено и файл пароля читается. |
