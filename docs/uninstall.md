# Удаление lazarus

Как полностью убрать `lazarus` с сервера — сам скрипт, симлинк и cron-задачи — **не потеряв бэкапы**.

Удаление **безопасно по умолчанию**: скрипт сносит только себя и свои cron-задачи, а каталог с архивами (`/opt/lazarus-backup/backup/`) **оставляет на месте**. Стереть бэкапы можно только отдельным явным подтверждением. Требуется `root` (`sudo`).

---

## TL;DR — 3 шага

1. Запустите `lazarus` и войдите в **Расширенный режим** (пункт `99` в главном меню).
2. Выберите пункт **`666. Удалить скрипт`**, подтвердите `y`.
3. На вопрос про каталог с бэкапами:
   - **просто нажмите Enter** — скрипт удалится, а все архивы и конфиг **сохранятся** в `/opt/lazarus-backup/`;
   - хотите стереть всё вместе с бэкапами — введите точно `DELETE-BACKUPS`.

Скрипт покажет, **сколько у вас бэкапов и сколько они весят**, прежде чем что-либо трогать.

---

## Как удалить

Удаление живёт в **Расширенном режиме** (в Простом меню его нет — защита от случайного нажатия).

```bash
sudo lazarus
```

```
   99.  Простой режим (короткое меню для новичков)
  666.  Удалить скрипт
    0.  Выход
Выбор: 666
```

> Если меню открылось в **Простом режиме** — сначала переключитесь в Расширенный (пункт `99`), затем появится пункт `666`.

Скрипт сначала посчитает бэкапы и спросит подтверждение:

```
  [WARN] Удаление LAZARUS: симлинк + /opt/lazarus-backup/lazarus-backup + cron-задачи.
  Бэкапов в каталоге: 12 шт (3.4G) — /opt/lazarus-backup/backup
Продолжить удаление скрипта? (y/N): y
```

Ответ **не `y`** (или Enter) — операция отменяется, ничего не меняется.

### Второй вопрос — удалять ли сам каталог с бэкапами

После удаления скрипта и симлинка, если каталог `/opt/lazarus-backup/` ещё существует, скрипт задаёт **отдельный** вопрос с таймером (60 секунд) и **безопасным дефолтом «сохранить»**:

```
  [WARN] Каталог /opt/lazarus-backup содержит 12 бэкапов (3.4G) + конфиг + пароль шифрования.
  [WARN] Удаление НЕОБРАТИМО. Для удаления введите точно:  DELETE-BACKUPS  (Enter/тайм-аут = сохранить)
```

- **Enter, пустой ввод или тайм-аут** → каталог и бэкапы **СОХРАНЯЮТСЯ**. Это то, что нужно почти всегда.
- Ровно `DELETE-BACKUPS` → каталог `/opt/lazarus-backup/` удаляется целиком **вместе с архивами, конфигом и паролем шифрования**. Необратимо.

Одной буквы `y` для стирания бэкапов **недостаточно** намеренно: в каталоге лежат все архивы, `config.env` и пароль шифрования (`.password`). Опечатка не должна стоить вам данных.

---

## Что удаляется

| Объект | Путь | Когда удаляется |
|---|---|---|
| Симлинк CLI | `/usr/local/bin/lazarus` | всегда (после `y`) |
| Установленный скрипт | `/opt/lazarus-backup/lazarus-backup` | всегда (после `y`) |
| Cron-задачи | строки с меткой `# LAZARUS-JOB-*` в crontab root | всегда (после `y`) |

После этого команда `lazarus` в системе больше не работает, а авто-бэкапы по расписанию не запускаются.

---

## Что НЕ удаляется (по умолчанию)

| Объект | Путь | Примечание |
|---|---|---|
| **Каталог с бэкапами** | `/opt/lazarus-backup/backup/` | все ваши архивы — **забрать вручную**, если каталог нужен |
| Конфиг | `/opt/lazarus-backup/config.env` | настройки цели, хранилища, расписания |
| Пароль шифрования | `/opt/lazarus-backup/.password` | без него зашифрованные бэкапы **не восстановить** |
| Лог | `/var/log/lazarus_backup.log` | остаётся в системе |
| Правило logrotate | `/etc/logrotate.d/lazarus` | остаётся; безвредно, удалить можно вручную (ниже) |

Пока вы **не** ввели `DELETE-BACKUPS`, весь каталог `/opt/lazarus-backup/` остаётся нетронутым — из него можно восстановиться даже после удаления скрипта (переустановив `lazarus` рядом). См. [Восстановление](restore.md).

> **Забрать бэкапы перед полной зачисткой.** Если планируете стереть каталог, сначала скопируйте нужные архивы:
> ```bash
> cp /opt/lazarus-backup/backup/lazarus_*.tar* /root/keep/
> # и НЕ забудьте пароль, если бэкапы зашифрованы:
> cp /opt/lazarus-backup/.password /root/keep/
> ```

## Полная зачистка (убрать и бэкапы тоже)

Если вы точно хотите стереть всё — сделайте это через тот же мастер, введя `DELETE-BACKUPS` на втором вопросе. Это удалит каталог целиком.

Если скрипт уже удалён (остался только каталог), доберите остатки вручную:

```bash
# каталог с архивами, конфигом и паролем шифрования — НЕОБРАТИМО
rm -rf /opt/lazarus-backup

# правило logrotate (uninstall его не трогает)
rm -f /etc/logrotate.d/lazarus

# лог (по желанию)
rm -f /var/log/lazarus_backup.log
```

> Cron-задачи мастер `666` убирает сам. Если удаляли скрипт руками — проверьте и почистите crontab: `crontab -l | grep LAZARUS-JOB` → при наличии `crontab -e` и уберите строки с `# LAZARUS-JOB-*`.

⚠️ После полной зачистки **зашифрованные бэкапы восстановить нельзя** — пароль хранился только в удалённом `/opt/lazarus-backup/.password`. Не удаляйте его, пока не убедитесь, что все нужные архивы расшифрованы или пароль сохранён в другом месте.

## Частые вопросы

| Вопрос | Ответ |
|---|---|
| Случайно ввёл `y`, но бэкапы нужны | Ничего страшного: `y` удаляет только скрипт и cron. Каталог сохраняется, пока вы **не** ввели `DELETE-BACKUPS`. |
| Как переустановить после удаления | Установите заново — см. [Установку](install.md). Если каталог `/opt/lazarus-backup/` сохранён, старые бэкапы и настройки подхватятся. |
| `Uninstall requires root (sudo)` | Мастер `666` требует root. Запустите `sudo lazarus`. |
| Пункта `666` нет в меню | Вы в Простом режиме. Переключитесь в Расширенный (пункт `99`). |
| Остались архивы, а скрипт удалён | Это штатно. Заберите файлы из `/opt/lazarus-backup/backup/` или переустановите `lazarus` для восстановления. |
