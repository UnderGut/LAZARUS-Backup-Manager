# Автоматизация (расписание, cron)

Как настроить автоматический бэкап по расписанию — через меню или вручную через cron. В **расширенном** режиме это отдельный пункт **3 «Авто-бэкап (расписание)»**; в **простом** режиме (куда попадает новичок) сначала переключитесь пунктом **99 «Расширенный режим»**.

Расписание хранится в системном `crontab` пользователя, под которым установлен lazarus (обычно `root`). Каждая задача помечается меткой `# LAZARUS-JOB-<ТИП>`, чтобы lazarus мог находить, обновлять и удалять только свои строки, не трогая чужие cron-задачи.

---

## TL;DR — 3 шага для новичка

1. Запустите `lazarus`. Если вы в простом режиме — нажмите **99 «Расширенный режим»**. Затем в меню выберите **3. Авто-бэкап (расписание)**.
2. Выберите тип задачи — **1. Полный бэкап**, потом расписание **2. Ежедневно (в 04:00)** ← рекомендуется.
3. Готово. lazarus сам прописал строку в cron и запомнит её. Проверить — там же увидите `[✓ Ежедневно 04:00]`.

Отдельно ничего писать в crontab не нужно. Ручные cron-рецепты (ниже) — только для необычных случаев (verify/отчёт по расписанию).

---

## Как это работает

- **Планировщик — системный cron.** lazarus не держит собственный демон; он пишет строки в `crontab`. Если cron остановлен — бэкапы не пойдут.
- **Задача = вызов CLI-команды.** Каждая строка вызывает `lazarus backup_full` (или `backup_db` / `backup_files`), лог пишется в `/var/log/lazarus_backup.log`.
- **Метка-маркер.** В конце каждой строки — комментарий `# LAZARUS-JOB-FULL` / `-DB` / `-FILES`. По нему lazarus отличает свои задачи от чужих.
- **Синхронизация с конфигом.** После любой правки расписания lazarus читает реальный crontab и записывает человекочитаемое состояние в `SCHEDULE_FULL` / `SCHEDULE_DB` / `SCHEDULE_FILES` (`config.env`). Истина — cron, конфиг лишь отражает его.
- **Что бэкапится.** По расписанию бэкапится **активная цель** (панель / бот). Если включён режим «обе цели» — каждая задача бэкапит **обе** (панель + бот).

## Настройка из меню

Главное меню (расширенный режим; из простого — сначала **99**) → **3. Авто-бэкап (расписание)** → экран `Авто-бэкап (расписание)`:

```
Авто-бэкап (расписание)

Бэкапим: Remnawave Panel

 1. Полный бэкап   (БД + файлы)     [— выкл]
 2. Только БД      (быстро, часто)  [— выкл]
 3. Только файлы                    [— выкл]

 Авто-бэкап полностью выключен. Рекомендуем: пункт 1 → «Ежедневно».

 0. Назад
```

Когда хотя бы одна задача активна, вместо подсказки появляется красный пункт **9. Отключить все авто-бэкапы**.

### Типы задач

| Пункт | Тип | CLI-команда | Метка cron |
|---|---|---|---|
| 1 | **Полный бэкап** (БД + файлы) | `lazarus backup_full` | `# LAZARUS-JOB-FULL` |
| 2 | **Только БД** (быстро, часто) | `lazarus backup_db` | `# LAZARUS-JOB-DB` |
| 3 | **Только файлы** | `lazarus backup_files` | `# LAZARUS-JOB-FILES` |

Типы независимы: можно, например, держать **Только БД** каждый час и **Полный** раз в сутки одновременно.

### Варианты расписания

Выбрав тип, попадаете на экран `Расписание: <тип>`:

```
Расписание: Полный бэкап
Сейчас: [— выкл]

 1. Ежечасно           в :00 каждого часа
 2. Ежедневно          в 04:00   ← рекомендуется
 3. Еженедельно        Пн, 04:00
 4. Своё время         ЧЧ:ММ, можно несколько через пробел
 5. Каждые N минут     число 1–59

 0. Назад
```

| Пункт | Расписание | Cron-строка (spec) |
|---|---|---|
| 1 | Ежечасно | `0 * * * *` |
| 2 | Ежедневно 04:00 | `0 4 * * *` |
| 3 | Еженедельно (Пн 04:00) | `0 4 * * 1` |
| 4 | Своё время (ЧЧ:ММ) | `ММ ЧЧ * * *` (по строке на каждое время) |
| 5 | Каждые N минут | `*/N * * * *` |

**Своё время (пункт 4)** — можно ввести несколько времён через пробел, например `09:00 18:30`. Каждое проверяется на диапазон (ЧЧ `0–23`, ММ `0–59`); невалидное — пропускается с предупреждением. Если валидных времён не осталось — расписание **не меняется** (существующая задача не удаляется).

**Каждые N минут (пункт 5)** — интервал `1–59`. Даёт строку `*/N * * * *`. Значения вне диапазона (`0`, `60+`) отклоняются.

> ⚠️ Интервал `0` **не** отключает задачу и вообще не принимается — это некорректный ввод. Для отключения используйте пункт **9**, а не «0».

### Отключение

Отключение расписания живёт на клавише **9**, а не на «0» (на «0» везде — «Назад», чтобы привычное «ноль = выйти» случайно не снесло расписание). Пункт «9» показывается только когда есть что отключать:

- На экране конкретного типа: **9. Отключить это расписание** — убирает cron-строку данного типа.
- На экране «Авто-бэкап»: **9. Отключить все авто-бэкапы** — с подтверждением удаляет все строки `# LAZARUS-JOB-*`.

## Ручные cron-рецепты

Для задач, которых нет в меню (проверка целостности, периодический отчёт), пропишите строки в crontab вручную:

```bash
crontab -e
```

Полезные рецепты (путь `/usr/local/bin/lazarus` — стандартный путь установки):

```cron
# Проверка целостности всех архивов раз в неделю (Вс 04:00) + отчёт в Telegram
0 4 * * 0 /usr/local/bin/lazarus --report-tg verify >> /var/log/lazarus_backup.log 2>&1

# Еженедельный отчёт о backup-активности в Telegram (Вс 04:00)
0 4 * * 0 /usr/local/bin/lazarus report weekly >> /var/log/lazarus_backup.log 2>&1

# Свой бэкап БД каждые 6 часов (не через меню)
0 */6 * * * /usr/local/bin/lazarus --yes backup_db >> /var/log/lazarus_backup.log 2>&1
```

`report` принимает `daily` / `weekly` / `month`. `verify` прогоняет `gzip -t` + проверку HMAC по всем архивам. Подробнее о верификации — в [backup.md](backup.md).

> Если пишете cron-строки для самих бэкапов вручную — используйте те же имена команд, что и меню: `backup_full`, `backup_db`, `backup_files`. Так lazarus увидит и корректно отобразит их состояние. Обязательно добавляйте флаг `--yes` (см. ниже).

### `--yes` обязателен для cron

Cron запускает команды **не в терминале** (нет интерактивного ввода). Без `--yes` (`-y`) lazarus, наткнувшись на подтверждение, зависнет или прервётся. Поэтому:

```bash
lazarus --yes backup_full     # правильно для cron
lazarus backup_full           # только для ручного запуска в терминале
```

Строки, которые ставит **меню** пункта 3, вызывают `backup_full`/`backup_db`/`backup_files` — эти legacy-команды по умолчанию неинтерактивны и не требуют `--yes`. Флаг `--yes` нужен, когда вы пишете cron-строку **сами** и используете команды, которые иначе спросили бы подтверждение.

## Блокировка параллельного запуска (flock)

lazarus защищён от одновременного запуска: перед бэкапом берётся эксклюзивная блокировка (`flock`). Если новая задача стартует, пока предыдущая ещё работает, — новая аккуратно завершится с сообщением:

```
Другой процесс бэкапа уже запущен (PID: 12345). Повторите позже.
```

Это важно для частых расписаний (**Ежечасно**, **Каждые N минут**): если один бэкап затянулся дольше интервала, следующий не наложится и не повредит данные — он просто пропустит запуск. Lock-файл не удаляется намеренно (эксклюзивность держит сам `flock`, а не наличие файла).

## Логи и их ротация

Все запуски по расписанию пишут в `/var/log/lazarus_backup.log` (в cron-строках это `>> /var/log/lazarus_backup.log 2>&1`).

Ротацию лога lazarus настраивает автоматически при установке:

- **Системный logrotate** (предпочтительно) — при установке создаётся `/etc/logrotate.d/lazarus`: `weekly`, `rotate 8`, `compress`. Если файл уже есть — не перезаписывается (ваши правки сохранятся).
- **Встроенная ротация** — fallback на системах без `/etc/logrotate.d` (например, alpine).

Проверить, какая ротация активна: `lazarus diag` → блок `LOG ROTATION`.

## Проверка и восстановление расписания

```bash
crontab -l | grep LAZARUS-JOB    # какие задачи lazarus реально прописаны
lazarus diag                     # snapshot состояния (в т.ч. cron и лог)
```

Если cron-задачи были удалены вручную, а в конфиге расписание осталось, lazarus при интерактивном запуске сам обнаружит расхождение и предложит:

```
Обнаружено несоответствие настроек и cron-задач

 1. Создать недостающие cron-задачи (восстановить)
 2. Синхронизировать настройки с cron (сбросить в 'Выкл')
 0. Пропустить (оставить как есть)
```

- **1** — восстановит cron-строки из сохранённого расписания.
- **2** — приведёт конфиг в соответствие с реальным (пустым) cron.

## Частые проблемы

| Симптом | Причина / решение |
|---|---|
| Задача в меню показана, но бэкапы не идут | Проверьте, запущен ли `cron`/`crond`. lazarus только пишет строки, выполняет их системный cron. |
| «Другой процесс бэкапа уже запущен» в логе | Предыдущий бэкап не успел завершиться до следующего запуска. Норма при частом расписании; увеличьте интервал или облегчите задачу (Только БД). |
| Cron-задача «зависла» / ждёт ввод | В ручной cron-строке нет `--yes`. Добавьте `--yes` — см. раздел выше. |
| Меню показывает `— выкл`, хотя строка в crontab есть | Строка без метки `# LAZARUS-JOB-*` (например, добавлена вручную с другим синтаксисом) — lazarus её «не видит». Приведите к формату команд `backup_full`/`backup_db`/`backup_files` с меткой. |
| Расписание пропало после ручной правки crontab | Восстановите через меню при запуске (диалог рассинхронизации) или заново задайте в пункте 3. |
| Лог `/var/log/lazarus_backup.log` разросся | Проверьте ротацию: `lazarus diag` → `LOG ROTATION`. При отсутствии `/etc/logrotate.d/lazarus` работает встроенная ротация. |
