# Удалённые хранилища (облако)

Как отправлять копии бэкапов **за пределы сервера** — в S3, WebDAV, FTP или через Rclone. Настраивается один раз через меню, дальше каждый бэкап автоматически уезжает в облако.

Зачем: если сервер погибнет (диск, хостер, вымогатель), локальные архивы погибнут вместе с ним. Вторая копия **вне сервера** (off-site) — то, что реально спасает данные.

---

## TL;DR — 3 шага для новичка

1. Запустите меню и откройте **Настройки → Удалённое хранилище** (в простом режиме пункта «Настройки» нет — сначала нажмите **99 «Расширенный режим»**; либо облако предложит настроить мастер первого запуска):
   ```bash
   lazarus
   ```
2. Выберите тип (проще всего — **1. S3-хранилище**), пройдите мастер (endpoint, bucket, ключи). Мастер сам проверит подключение перед сохранением.
3. Готово: со следующего бэкапа архив автоматически уходит в облако. Проверить руками — `lazarus s3 test` и `lazarus s3 list`.

Данные в примерах ниже демонстрационные.

---

## Как это работает

- Копия в облако отправляется **автоматически** после создания архива — тем же прогоном, что и локальный бэкап и отправка в Telegram.
- Управляет выгрузкой флаг `SEND_TO_REMOTE` (по умолчанию `true`). Тип хранилища — `REMOTE_STORAGE_TYPE` (`off` = выключено).
- Для S3 после загрузки идёт **проверка целостности** (см. ниже): размер и контрольная сумма должны совпасть — иначе выгрузка считается неуспешной.
- Локальная копия по умолчанию **остаётся на сервере**. Удалять её после отправки можно, но это отдельная опасная опция (`DELETE_LOCAL_AFTER_REMOTE_UPLOAD`).

---

## Поддерживаемые типы

Мастер `configure_remote_storage` предлагает 4 типа (порядок — по рекомендуемости):

| № в меню | Тип | Для кого |
|---|---|---|
| 1 | **S3-хранилище** ← рекомендуется | AWS, Cloudflare R2, Yandex Cloud, MinIO и другие S3-совместимые |
| 2 | **WebDAV** | Яндекс.Диск, Nextcloud — если облако уже есть |
| 3 | **FTP / FTPS** | классический файловый сервер |
| 4 | **Rclone** | Google Drive, Dropbox — нужен заранее настроенный `rclone config` |

Пункт **9. Отключить удалённое хранилище** появляется, только когда хранилище уже настроено (сбрасывает тип в `off`). **0. Назад** — выход без изменений.

## Настройка из меню

Путь: **главное меню → Настройки → Удалённое хранилище** (из простого режима — сначала пункт **99 «Расширенный режим»**).

```
Настройка удалённого хранилища
Вторая копия бэкапа вне этого сервера: если сервер погибнет — данные уцелеют.

Сейчас подключено: S3 → my-backups/lazarus/prod
  Endpoint: https://s3.example.com

Куда отправлять копии:
 1. S3-хранилище   — AWS, Cloudflare R2, Yandex Cloud, MinIO  ← рекомендуется
 2. WebDAV         — Яндекс.Диск, Nextcloud: если облако уже есть
 3. FTP / FTPS     — классический файловый сервер
 4. Rclone         — Google Drive, Dropbox: нужен настроенный rclone

 9. Отключить удалённое хранилище
 0. Назад
```

После ввода данных мастер проверяет соединение (`head-bucket` для S3, тестовое подключение для остальных). Если проверка не прошла — предложит **сохранить настройки несмотря на ошибку (y/N)**; по умолчанию нет.

### FTP / WebDAV / Rclone

Мастер собирает итоговый URL из **адреса сервера** + **папки** (пустая папка = корень), затем спрашивает пользователя и пароль (для Rclone логин/пароль не нужны — берётся имя remote из `rclone listremotes`).

```
Адрес сервера: https://webdav.yandex.ru
Папка: Backup/Lazarus     → https://webdav.yandex.ru/Backup/Lazarus
Пользователь: ivan
Пароль (или токен приложения): ********
```

## Настройка S3

Шаги мастера S3 (`Настройка S3 Storage`):

- Если **AWS CLI** не установлен — мастер предложит поставить его автоматически (~100 MB, с учётом архитектуры x86_64/aarch64).
- **Шаг 1/5 — провайдер.** Выбор подставляет разумные значения endpoint/region:

| № | Провайдер | Endpoint по умолчанию | Region по умолчанию |
|---|---|---|---|
| 1 | AWS S3 | (пусто — стандартный) | `us-east-1` |
| 2 | MinIO | `http://localhost:9000` | `us-east-1` |
| 3 | RustFS | `http://localhost:8333` | `us-east-1` |
| 4 | Yandex Cloud Object Storage | `https://storage.yandexcloud.net` | `ru-central1` |
| 5 | Selectel Cloud Storage | `https://s3.storage.selcloud.ru` | `ru-1` |
| 6 | Cloudflare R2 | `https://<account-id>.r2.cloudflarestorage.com` | **`auto`** |
| 7 | Backblaze B2 | `https://s3.<region>.backblazeb2.com` | из endpoint (напр. `us-west-001`) |
| 8 | Другой S3-совместимый | — | `us-east-1` |

- **Шаг 2/5 — Endpoint URL.** Для AWS оставить пустым. Формат проверяется (`http(s)://host[:port][/path]`), при подозрении — предупреждение, но можно продолжить.
- **Шаг 3/5 — Bucket и путь.** Bucket обязателен; путь-префикс опционален (`lazarus/prod` → `s3://bucket/lazarus/prod/`).
- **Шаг 4/5 — Регион.**
- **Шаг 5/5 — Credentials** (Access Key ID + Secret Access Key, ввод секрета скрыт).

### Провайдерские нюансы

- **Cloudflare R2**: регион **обязан быть `auto`** — иначе `SignatureDoesNotMatch`. Account ID для endpoint — в Cloudflare dashboard → R2 → Overview.
- **Backblaze B2**: регион вытягивается из endpoint автоматически (`s3.<region>.backblazeb2.com`), вводить вручную не нужно.
- Ключи S3 сохраняются не в env, а в приватный файл с правами `0600`.

Итоговые значения ложатся в конфиг:

| Ключ | Что |
|---|---|
| `REMOTE_STORAGE_TYPE=s3` | тип хранилища |
| `S3_ENDPOINT` | endpoint URL (пусто для AWS) |
| `S3_BUCKET` / `S3_PATH` | бакет и префикс внутри |
| `S3_REGION` | регион (`auto` для R2) |
| `S3_ACCESS_KEY` / `S3_SECRET_KEY` | креды |

## Проверка целостности после загрузки

Для S3 просто «залить» мало — надо убедиться, что файл **реально доехал и не побился**. После успешной `s3 cp` вызывается `_s3_verify_uploaded`:

1. `head-object` → **размер объекта** (`ContentLength`) на сервере сверяется с локальным размером.
2. Для не-multipart загрузки (single PUT) **ETag = MD5**: сверяется с локальной контрольной суммой (`md5sum`). Для multipart ETag считается иначе — тогда только сверка размера.

Результаты:
- **size + MD5 совпали** → `☁️ S3: OK` (verified), после чего запускается ротация на S3.
- **не совпали** → `☁️ S3: Verify FAIL`, выгрузка считается **неуспешной** (удалённый файл повреждён).
- `head-object` не отработал (нет прав / eventual consistency) → мягкий warn, даётся повторная попытка.

Сама загрузка устойчива к сбоям: до 3 попыток с нарастающей паузой (5 → 15 → 45 c) и очисткой зависших multipart-частей между ними.

## Удаление локальной копии после отправки

По умолчанию локальный архив **остаётся** на сервере (`DELETE_LOCAL_AFTER_REMOTE_UPLOAD=false`). Опция удаления живёт в **Настройки → Ротация → пункт 6** и помечена как ОПАСНАЯ: при сбое сети можно потерять единственную копию.

| Режим | Когда удаляет локальную копию |
|---|---|
| `false` | никогда (безопасно, по умолчанию) |
| `any` | если доставил хотя бы один канал (Telegram или remote) |
| `all` | только если **все** настроенные каналы успешны |
| `remote_only` | если доставил именно remote (S3/FTP/WebDAV); Telegram не учитывается |

Ключевое: удаление происходит **только после подтверждённой доставки** — для S3 это значит **после сверки размера/ETag**. Если verify провалился, локальная копия не трогается. Режимы `any`/`remote_only` при выключенном remote предупреждают (Telegram ограничен ~50 MB — для крупных бэкапов это риск).

## Ротация на S3

Чтобы облако не разрасталось, старые архивы можно чистить автоматически — `S3_RETENTION_DAYS` (по умолчанию `0` = не удалять).

- Запускается **после каждой успешной выгрузки** (`_s3_rotate_old`), сбой ротации не влияет на статус бэкапа.
- Удаляются **только свои** ключи вида `lazarus_*` / `lazarus_panel_*` (семейства `db`/`files`/`full`/`inc`) **непосредственно внутри `S3_PATH`** — чужие объекты бакета и вложенные подпапки не трогаются никогда.
- **Новейший архив каждой цели** (бот / панель) не удаляется, даже если он старше N дней — offsite не может опустеть из-за сбитых часов или долгого простоя.

Настройка в конфиге:
```env
S3_RETENTION_DAYS="14"   # хранить архивы на S3/R2 14 дней; 0 = не удалять
```

## CLI: команды `lazarus s3`

Быстрые операции без меню (алиас — `lazarus -S`):

| Команда | Что делает |
|---|---|
| `lazarus s3 test` (`-t`) | проверить подключение к S3 (endpoint/region/bucket + `head-bucket`) |
| `lazarus s3 list` (`-l`) | список файлов в `s3://BUCKET/PATH/` (human-readable) |
| `lazarus s3 upload <файл>` (`-u`) | загрузить произвольный файл в S3 (с проверкой целостности) |
| `lazarus s3 rotate [N]` (`-r`) | удалить свои архивы старше N дней (без N — берёт `S3_RETENTION_DAYS`) |

```bash
lazarus s3 test
lazarus s3 list
lazarus s3 upload /root/backups/lazarus_panel_full_20260719.tar.gz.enc
lazarus s3 rotate 14
```

`lazarus s3 rotate` уважает `--dry-run` — покажет, что удалил бы, ничего не трогая. Все команды `s3` требуют, чтобы `REMOTE_STORAGE_TYPE=s3` был уже настроен.

## Частые проблемы

| Симптом | Причина / решение |
|---|---|
| `SignatureDoesNotMatch` на Cloudflare R2 | Регион должен быть **`auto`**, а не `us-east-1`. Переввести в мастере (шаг 4/5). |
| `S3 не настроен!` при `lazarus s3 …` | `REMOTE_STORAGE_TYPE` не равен `s3`. Настройте через Настройки → Удалённое хранилище. |
| `☁️ S3: Verify FAIL` | Размер/ETag удалённого файла не сошлись — объект повреждён; бэкап не считается доставленным. Повторить выгрузку, проверить сеть/лимиты бакета. |
| AWS CLI ставится с ошибкой | Проверьте архитектуру (`uname -m`) и поставьте AWS CLI v2 вручную. |
| Ротация ничего не удаляет | `S3_RETENTION_DAYS=0` (выключена) либо архивы лежат во вложенной подпапке, а не прямо в `S3_PATH`. |
